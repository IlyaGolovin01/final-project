## 1. Что нужно для запуска

* Python 3.10 или новее.
* Токен бота от [@BotFather](https://t.me/BotFather): напишите ему `/newbot`,
  укажите имя и адрес бота, скопируйте выданный токен вида
  `123456789:AAE...`. Токен — это пароль от бота, его нельзя публиковать.
* Telegram ID сотрудников, которые будут обрабатывать заявки (см. раздел 4).
* Ключ Whisper API — только если нужна расшифровка голосовых сообщений
  (см. раздел 10). Без него бот работает, просто просит написать текстом.

Проверить версию Python:

```bash
python --version
```

## 2. Установка

Откройте командную строку в папке проекта и выполните:

```bash
pip install -r requirements.txt
```

Устанавливаются две библиотеки: `pyTelegramBotAPI` (работа с Telegram) и
`requests` (запросы к Whisper API). Больше ничего не требуется — поиск по базе
знаний написан на стандартной библиотеке Python.

Затем создайте файл настроек из шаблона:

```bash
copy .env.example .env      :: Windows
cp .env.example .env        #  Linux / macOS
```

## 3. Настройка файла .env

`.env` — простой текстовый файл в формате `ПАРАМЕТР=значение`, по одному на
строку. Строки, начинающиеся с `#`, — комментарии. Кавычки вокруг значений не
нужны. После любого изменения `.env` бота нужно перезапустить.

**Обязательный параметр один:**

| Параметр | Что это |
|---|---|
| `BOT_TOKEN` | Токен от @BotFather. Без него бот не запустится |

**Сотрудники** (Telegram ID через запятую, можно оставить пустым и заполнить позже):

| Параметр | Кто это |
|---|---|
| `ADMIN_IDS` | Суперадминистраторы: видят оба отдела, статистику, `/export`, `/reload` |
| `IT_STAFF_IDS` | Технический отдел: сайт, оплата, личный кабинет |
| `SALES_STAFF_IDS` | Отдел продаж: товары, заказы, доставка, возвраты, гарантия |

**Данные магазина.** Подставляются в тексты бота, поэтому важно держать их
актуальными:

| Параметр | Пример |
|---|---|
| `SHOP_NAME` | `Продаем все на свете` |
| `SHOP_SITE` | `https://prodaem-vse.example` |
| `SUPPORT_PHONE` | `8 800 000-00-00` |
| `SUPPORT_EMAIL` | `support@prodaem-vse.example` |
| `WORKING_HOURS` | `ежедневно с 09:00 до 21:00 (МСК)` |
| `SLA_HOURS` | `24` — обещанный срок первого ответа, в часах |

**Файлы и журналы:**

| Параметр | По умолчанию | Комментарий |
|---|---|---|
| `DB_PATH` | `support.db` в папке проекта | Файл базы данных. Если меняете — указывайте полный путь |
| `FAQ_PATH` | `data/faq.json` в папке проекта | Файл базы знаний. Если меняете — указывайте полный путь |
| `LOG_LEVEL` | `INFO` | `DEBUG` — подробно, `WARNING` — только проблемы |
| `LOG_FILE` | не задан | Укажите, например, `bot.log`, чтобы писать журнал в файл |

Пустое значение любого параметра, кроме `BOT_TOKEN` и списков сотрудников,
означает «использовать значение по умолчанию».

**Тонкая настройка поиска.** Менять стоит только если бот заметно
ошибается — см. раздел 13.

| Параметр | По умолчанию | Что делает |
|---|---|---|
| `FAQ_DIRECT_THRESHOLD` | `0.50` | Выше этой оценки бот отвечает сразу. Больше значение — строже бот |
| `FAQ_SUGGEST_THRESHOLD` | `0.20` | Выше этой оценки предлагает похожие вопросы кнопками |
| `FAQ_MAX_SUGGESTIONS` | `3` | Сколько вариантов показать в подсказке |

**Прочее:**

| Параметр | По умолчанию | Что делает |
|---|---|---|
| `NOTIFY_STAFF` | `true` | Присылать сотрудникам новые заявки в личку |
| `MAX_TICKET_TEXT` | `2000` | Максимальная длина текста заявки |
| `ADMIN_PAGE_SIZE` | `5` | Сколько заявок на странице в панели поддержки |

> **Важно:** `.env` содержит токены. Не отправляйте его в мессенджерах, не
> прикладывайте к письмам и не добавляйте в git — для этого в проекте есть
> `.gitignore`. Делиться с коллегами нужно файлом `.env.example`.

## 4. Кто такие сотрудники и админы

Права определяются исключительно Telegram ID в `.env`.

**Как узнать Telegram ID сотрудника.** Попросите его найти бота в Telegram,
нажать «Старт» и отправить команду `/id` — бот ответит числом. Это число и
нужно вписать в `.env`. Никаких других способов не требуется.

| Роль | Как задаётся | Что доступно |
|---|---|---|
| Клиент | по умолчанию | FAQ, создание заявок, свои заявки |
| Сотрудник отдела | `IT_STAFF_IDS` или `SALES_STAFF_IDS` | Панель `/admin` **только по своему отделу**: списки, ответы, закрытие, передача в другой отдел, статистика, вопросы без ответа |
| Суперадминистратор | `ADMIN_IDS` | То же по **обоим** отделам, плюс `/export` (выгрузка CSV) и `/reload` (перечитать базу знаний) |

Один человек может быть в нескольких списках. Пример строки с несколькими
сотрудниками:

```
SALES_STAFF_IDS=111111111,222222222,333333333
```

Сотрудник, который получил доступ, увидит панель после команды `/admin`.
Если он видит сообщение «Панель поддержки доступна только сотрудникам» —
значит его ID не попал в `.env` или бота не перезапустили.

## 5. Запуск и остановка

```bash
python bot.py
```

При успешном старте в консоли появятся строки вида:

```
Бот запущен: @prodaem_support_bot (Поддержка «Продаем все на свете»)
Сотрудники: суперадмины (111111111,), технический отдел (222222222,), отдел продаж (333333333,)
Распознавание голоса: отключено
```

Остановка — `Ctrl+C` в окне консоли. Бот работает, пока запущен этот процесс:
если закрыть окно, бот перестанет отвечать. Для постоянной работы разместите
проект на сервере и настройте автозапуск (systemd в Linux, «Планировщик
заданий» или NSSM в Windows).

Перед стартом бот проверяет настройки и печатает предупреждения — например,
что не задан ни один сотрудник или что для голосовых сообщений выбран режим
`openai`, но не указан ключ. Ошибки, при которых запуск невозможен (нет или
испорчен `BOT_TOKEN`, отсутствует файл базы знаний), выводятся отдельно, и бот
завершает работу.

**Что переживает перезапуск, а что нет.** Заявки, переписка и журнал вопросов
хранятся в файле базы данных и никуда не исчезают. Сообщения, которые клиенты
прислали при выключенном боте, Telegram хранит около суток — после запуска бот
их обработает, так что обращение не потеряется. Незаконченные диалоги (клиент
начал описывать проблему, но не отправил заявку) хранятся в памяти и
сбрасываются. Клиент просто начнёт заново — данные не теряются, потому что
заявка сохраняется только в момент отправки.

## 6. Что видит клиент

Внизу экрана — постоянное меню из четырёх кнопок:

* **❓ Частые вопросы** — темы списком, внутри тем сами вопросы.
* **🧑‍💼 Связаться со специалистом** — создание заявки.
* **📋 Мои заявки** — статусы и вся переписка по своим обращениям.
* **ℹ️ Контакты и режим работы** — телефон, почта, сайт, кто чем занимается.

Главный сценарий — клиент просто пишет вопрос своими словами. Дальше возможны
три исхода: бот отвечает сразу, предлагает похожие вопросы кнопками или
предлагает создать заявку и сам подсказывает подходящий отдел.

Под каждым ответом есть кнопки **👍 Помогло** и **👎 Не помогло**. «👎»
сразу предлагает передать вопрос специалисту, а отзыв попадает в статистику.

Создание заявки идёт по шагам: выбор отдела → описание проблемы → контакт
(можно пропустить) → предпросмотр → отправка. Клиент получает номер вида
`TS-2026-0001`, а сотрудники нужного отдела — уведомление в личку. Ответы
специалиста приходят клиенту в тот же чат; дополнить обращение можно через
«📋 Мои заявки» → «💬 Дополнить заявку». Любой шаг отменяется командой
`/cancel` или кнопкой «✖️ Отмена».

## 7. Панель поддержки: работа с заявками

Команда `/admin` открывает панель. Разделы:

* **Открытые — <отдел>** — новые (🆕) и взятые в работу (⏳) заявки с
  постраничной навигацией. Суперадминистратор видит кнопку на каждый отдел,
  сотрудник — только на свой.
* **🙋 Мои заявки в работе** — то, что вы взяли на себя.
* **📊 Статистика** — заявки по статусам и отделам, среднее время закрытия,
  доля вопросов, на которые бот ответил сам, самые частые темы.
* **🕳 Вопросы без ответа** — то, на что бот не смог ответить. Главный
  инструмент для пополнения базы знаний.
* **🔎 Найти заявку по номеру** — принимает `TS-2026-0007` или просто `7`.

Внутри карточки заявки доступны действия:

| Кнопка | Что делает |
|---|---|
| 🙋 Взять в работу | Статус → «в работе», вы становитесь исполнителем, клиент получает уведомление |
| ✉️ Ответить клиенту | Ваше следующее сообщение уйдёт клиенту в чат и сохранится в переписке. Новая заявка при этом автоматически берётся в работу |
| ✅ Закрыть заявку | Попросит описать решение; текст уйдёт клиенту вместе с уведомлением о закрытии |
| ↪️ Передать в другой отдел | Меняет отдел, пишет пометку в переписку и уведомляет сотрудников нового отдела |
| ↩️ Переоткрыть | Возвращает закрытую заявку в работу |

Каждый шаг с вводом текста можно прервать командой `/cancel`.

**Жизненный цикл заявки:** `новая` → `в работе` → `закрыта`. Если клиент
допишет что-то в закрытую заявку, она автоматически переоткроется, и сотрудники
получат уведомление, — потерять обращение нельзя.

**Рекомендация по работе:** берите заявку в работу до того, как начнёте
разбираться. Так коллеги видят, что обращение занято, и не дублируют ответ.

## 9. Редактирование базы знаний (вопросы и ответы)

Все вопросы и ответы лежат в `data/faq.json`. Это обычный текстовый файл —
правьте его в «Блокноте», VS Code или Notepad++, **сохраняя кодировку UTF-8**.

Файл состоит из двух списков: `categories` (темы) и `items` (вопросы).

Категория:

```json
{
  "id": "delivery",
  "title": "Доставка",
  "emoji": "🚚",
  "dept": "sales"
}
```

Вопрос:

```json
{
  "id": "delivery_info",
  "cat": "delivery",
  "dept": "sales",
  "q": "Как узнать информацию о доставке?",
  "a": "Информацию о доставке вы можете найти на странице оформления заказа на нашем сайте. Там указаны доступные способы доставки и сроки.",
  "kw": ["доставка", "сроки доставки", "способы доставки", "когда привезут"]
}
```

Поля вопроса:

| Поле | Назначение |
|---|---|
| `id` | Уникальный код на латинице. Используется в статистике — менять у существующих вопросов не стоит |
| `cat` | `id` категории, в которой показывать вопрос |
| `dept` | Куда передать заявку, если ответ не помог: `it` или `sales` |
| `q` | Текст вопроса. Виден на кнопке и в заголовке ответа |
| `a` | Текст ответа |
| `kw` | Ключевые слова и фразы для поиска — самое важное поле |

**Про `kw`.** Именно ключевые слова определяют, найдёт ли бот ответ. Пишите
так, как спрашивают клиенты, включая разговорные формулировки и частые
опечатки: `["где мой заказ", "статус заказа", "отследить", "трек-номер",
"когда приедет"]`. Падежи и окончания бот обрабатывает сам, поэтому достаточно
одной формы слова. 8–15 ключевых слов на вопрос — хороший ориентир.

**В ответах (`a`) используйте обычный текст, без HTML-разметки** — бот выводит
их как есть, теги отобразятся буквально. Разбивать на абзацы можно
последовательностью `\n\n` внутри строки JSON.

В текст ответа можно вставить подстановки — бот заменит их на данные из `.env`:

| Подстановка | Заменяется на |
|---|---|
| `{shop}` | `SHOP_NAME` |
| `{site}` | `SHOP_SITE` |
| `{phone}` | `SUPPORT_PHONE` |
| `{email}` | `SUPPORT_EMAIL` |
| `{hours}` | `WORKING_HOURS` |
| `{sla}` | `SLA_HOURS` |

Например: `Позвоните нам по {phone} — работаем {hours}.`

**Порядок работы при пополнении базы:**

1. Откройте в панели «🕳 Вопросы без ответа» — там реальные формулировки клиентов.
2. Добавьте новый вопрос в `items` (или допишите ключевые слова к существующему).
3. Сохраните файл в UTF-8.
4. Отправьте боту `/reload`. Бот ответит, сколько категорий и вопросов загрузил.
5. Проверьте: напишите боту тот самый вопрос из списка.

Если в JSON есть синтаксическая ошибка, `/reload` покажет её текст, а бот
продолжит работать на прежней версии базы — сломать поддержку опечаткой нельзя.
Самые частые ошибки в JSON: лишняя запятая перед `}` или `]`, пропущенная
запятая между элементами, «умные» кавычки вместо обычных `"`. Проверить файл
можно на сайте jsonlint.com.

## 10. Голосовые сообщения

По умолчанию расшифровка выключена (`STT_PROVIDER=none`): на голосовое бот
вежливо просит написать текстом. Чтобы включить, укажите в `.env`:

```
STT_PROVIDER=openai
OPENAI_API_KEY=sk-...
STT_MODEL=whisper-1
STT_LANGUAGE=ru
STT_TIMEOUT=60
STT_MAX_DURATION=120
```

и перезапустите бота. `STT_LANGUAGE` можно оставить пустым — тогда язык
определит сам сервис. `STT_TIMEOUT` — сколько секунд ждать ответа сервиса,
прежде чем сообщить клиенту, что расшифровка не удалась.

После этого голосовые работают везде, где работает
текст: и как вопрос к базе знаний, и как описание проблемы в заявке. Бот
показывает расшифровку клиенту, чтобы тот видел, что именно распознано.
Заявки, созданные голосом, помечаются в карточке как «🎤 голосовое сообщение».

Сообщения длиннее `STT_MAX_DURATION` секунд не обрабатываются — это защита от
случайных многоминутных записей. Если сервис распознавания недоступен, бот
скажет об этом и предложит написать текстом; заявки при этом не теряются.

Расшифровка — платная услуга внешнего сервиса. `OPENAI_BASE_URL` позволяет
указать совместимый шлюз вместо `api.openai.com`.

## 11. База данных: что где хранится

Файл `support.db` (формат SQLite). Открыть и посмотреть можно бесплатной
программой **DB Browser for SQLite**.

**`tickets` — заявки к специалистам** (главная таблица, требование «хранить
все запросы к специалистам в отдельной таблице»):

| Поле | Что содержит |
|---|---|
| `id` | Внутренний номер |
| `ticket_no` | Номер для клиента, например `TS-2026-0001` |
| `user_id`, `username`, `full_name` | Кто обратился |
| `department` | `it` или `sales` |
| `message` | Текст обращения |
| `contact` | Контакт, который оставил клиент |
| `status` | `new`, `in_progress`, `closed` |
| `source` | `text` или `voice` |
| `assignee_id`, `assignee` | Кто взял в работу |
| `resolution` | Описание решения при закрытии |
| `created_at`, `updated_at`, `closed_at` | Даты и время |

**`ticket_comments`** — вся переписка по заявкам: кто написал, текст, время,
флаг «сообщение от сотрудника».

**`users`** — те, кто писал боту: имя, username, дата первого и последнего
обращения.

**`faq_log`** — журнал вопросов: текст запроса, найденный вопрос, оценка
совпадения, результат (`answered`, `suggested`, `not_found`, `category`),
источник (`text` / `voice`) и отзыв 👍/👎. На этих данных строятся статистика
и экран «Вопросы без ответа».

Выгрузка заявок в CSV — команда `/export` (только суперадминистраторам). Файл
открывается в Excel; разделитель — точка с запятой, кодировка UTF-8 с BOM,
поэтому русский текст не «поедет».

## 12. Резервное копирование

Достаточно копировать три вещи: `support.db` (заявки и переписка),
`data/faq.json` (база знаний) и `.env` (настройки, храните в защищённом месте).

Копировать `support.db` лучше при остановленном боте. Если бот работает,
скопируйте заодно файлы `support.db-wal` и `support.db-shm`, если они есть, —
иначе в копию могут не попасть последние записи. Разумная периодичность —
ежедневно, с хранением копий за последнюю неделю.

## 13. Диагностика проблем

**Бот не запускается: «Не задан BOT_TOKEN».**
В папке нет файла `.env`, либо строка `BOT_TOKEN=` пустая. Создайте `.env` из
`.env.example` и впишите токен.

**«Telegram не принял токен».**
Токен скопирован с ошибкой (лишний пробел, обрезан) или бот удалён в
@BotFather. Запросите токен заново командой `/token` у @BotFather.

**Бот запустился, но не отвечает.**
Проверьте, что запущен ровно один экземпляр: два процесса с одним токеном
«перетягивают» сообщения друг у друга, и ответы теряются. Закройте лишние окна
консоли и запустите снова.

**Сотрудник не видит панель `/admin`.**
Его ID не в `.env`, либо бота не перезапустили после правки, либо ID указан с
опечаткой. Пусть сотрудник пришлёт `/id` и сверьте число посимвольно.

**Уведомления о новых заявках не приходят.**
Сотрудник должен сам первым написать боту `/start` — Telegram не позволяет
писать пользователю, который не начал диалог. Также проверьте, что
`NOTIFY_STAFF=true`.

**Бот отвечает не на тот вопрос.**
Уберите пересекающиеся ключевые слова у похожих вопросов и увеличьте
`FAQ_DIRECT_THRESHOLD` (например, до `0.60`) — бот станет строже и чаще будет
предлагать варианты кнопками вместо одного ответа.

**Бот часто не находит ответ, хотя он есть.**
Посмотрите «🕳 Вопросы без ответа» и добавьте оттуда формулировки в `kw`. Это
работает лучше, чем снижать порог. Если решили снижать — уменьшайте
`FAQ_DIRECT_THRESHOLD` шагами по `0.05`.

**`/reload` пишет об ошибке в JSON.**
В файле опечатка. Проверьте его на jsonlint.com. Бот продолжает работать на
прежней версии базы знаний, так что клиенты ничего не заметят.

**Голосовые не распознаются.**
Проверьте `STT_PROVIDER=openai`, наличие `OPENAI_API_KEY`, длину записи
(лимит `STT_MAX_DURATION`) и доступ к сети с сервера. Подробности ошибки
видны в журнале при `LOG_LEVEL=DEBUG`.

**Ничего из перечисленного не помогло.**
Поставьте `LOG_LEVEL=DEBUG` и `LOG_FILE=bot.log`, перезапустите бота,
повторите проблемное действие и передайте `bot.log` разработчику.

## 14. Регулярное обслуживание

**Ежедневно.** Просмотреть новые (🆕) заявки, взять в работу и ответить в
пределах обещанного срока (`SLA_HOURS`).

**Раз в неделю.** Открыть «🕳 Вопросы без ответа», добавить 2–3 новых вопроса
в `data/faq.json`, применить через `/reload`. Заглянуть в «📊 Статистику»:
если доля самостоятельных ответов бота растёт, база знаний работает.

**Раз в месяц.** Проверить актуальность телефона, почты, сайта и режима работы
в `.env`. Убедиться, что резервные копии создаются. Сверить списки сотрудников
с фактическим составом отделов.
